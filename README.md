**# Video Understanding MCP Server**

让具有视觉能力的LLM通过智能抽帧“观看”连贯视频——不再只是看一张图，二是理解一整段画面。





**## 它能做什么**



\- 从 URL 下载视频，用 OpenCV 进行智能抽帧

\- 帧间差异算法自动跳过画面没变化的帧，减少冗余

\- 每 3 秒保底保留一帧，避免静态对话场景丢失

\- 返回关键帧图片给 LLM，由 LLM 自己"看图说话"

\- 封装为 MCP Server，可接入 Claude 等具有视觉能力的 LLM





**## 架构**



视频文件 → 智能抽帧 → 返回关键帧 → LLM 自己看图分析 → 输出观后感





**## 技术栈**



\- Python

\- OpenCV（视频处理、帧间差异计算）

\- NumPy（矩阵运算）

\- MCP SDK（Model Context Protocol）





**## 遇到的问题**



\- 视频旋转：手机录制的视频带有旋转元数据，导致抽帧方向错误。

&#x20; 由于不同设备的旋转方向不同，最终选择删除代码中的硬编码旋转，

&#x20; 交给用户自行用 ffmpeg 修正。

\- 手机端无法直接传视频路径：手机上的 Claude 没有本地文件路径，

&#x20; 也没有直接上传视频的方式。解决思路是先将视频上传到可访问的 URL，

&#x20; 再传给 MCP Server 下载处理。

\- 帧图片的编码格式：虽然最终版本不调用视觉 API，但在开发过程中

&#x20; 发现图片需要转为 base64 字符串才能通过 JSON 传输。

&#x20; 最终 server 用 cv2.imencode + base64.b64encode 处理。
